# 项目事实源建议格式（按需加载）

这是 `agent-handoff` §15 的可选格式，已有项目文档不强行迁移。权威事实源可为项目 Git 仓库或有 revision/并发保护的知识库；交接 Hub 只保存任务指针。

```text
docs/project-memory/
  INDEX.md                   # 项目标识、事实源、分支和模块导航
  STATUS.md                  # 当前态快照（替换，勿堆积历史）
  decisions/ADR-0001.md     # 现行决定与被取代关系
  bugs/BUG-0001.md          # 根因、修复、回归证据
  logs/2026.md              # 逐次变更日志，年度分卷
```

项目索引标注现行模块规则、活跃 ADR/Bug 与相关日志 ID。仓库相对路径可跨 Agent 携带；不要把本机路径、凭据或原会话上下文当作跨设备事实。

日志条目至少包含：`ID`（稳定唯一，如 `PC-20260924T063000Z-a1b2c3`，并发不使用当日序号）、日期、执行 Agent 标识（自由文本）、任务/模块、基线分支与 revision、实际改动、决策依据/取舍、验证结果与环境、关联 ADR/Issue/PR/提交、风险/后续和可证实的本地状态。重试先检索既有 ID，不重复追加。不要预填尚未产生的最终提交 SHA；可用日志 ID 在 Git 历史中定位包含该日志的提交。日志被后续结论修正时添加更正条目并更新当前态，保留旧指针。

不具备写权限的 Agent 应只读，并明确输出建议补丁/文字与「未写回」状态；不暗示已提交或已同步。多个后端无法原子提交时分别报告各自 revision 与同步情况。
