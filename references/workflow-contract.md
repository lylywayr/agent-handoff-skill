# 统一任务路由与安全状态（agent-handoff 的组成部分）

本文件用于落地 SKILL.md §15；不是第二个 Skill。项目事实源由项目显式绑定。工作区状态和权限按动作判断，不能因 Agent 身份或“装了 Skill”自动获得写权限。

| 任务 | 开工证据 | 可写内容 | 收尾状态 |
|---|---|---|---|
| 只读/问答 | 有项目则核对标识和可得版本，按主题读取 | 无 | 回答来源与新鲜度；不记日志、不提交 |
| 讨论/方案 | 现行约束与相关决策 | 用户明确要求保存且授权时仅保存草案，标 proposed | 不记已实现版本 |
| 实施中/WIP | 远端基线、本地残留、关联模块 | 仅获准的工作区文件；交接可写 WIP 指针 | 不把 WIP 写成已交付事实 |
| 已验证的变更 | 实际 diff、测试、基线与目标分支 | 项目状态、相应 ADR/Bug、单条唯一日志；与改动同提交 | 分别判本地已写、已提交、远端已同步 |
| 跨 Agent 交接 | 项目权威记录 + 未提交残留位置 | 仅启用 hub 时写交接摘要与指针 | hub 与项目仓库分别核实；不宣称原子一致 |
| 新项目创建 | 用户批准的目录、所有者、可见性、分支、目的 | 本地仓库；远端创建/首次推送需包含在授权内 | 本地仓库、远端对象、远端分支分别验收 |

## 权限门槛

按动作独立判断：本地新建/编辑、创建本地 Git、commit、创建远端（owner/name/visibility）、push、公开、部署/生产更改。用户明确委托“实现并提交/同步”的通常许可只覆盖指定项目和约定分支；项目规则更严格时按规则执行。不能从一次推送授权推断以后每次都获授权，除非项目绑定写有持续授权范围；不能把“查看、研究、讨论”推断成写入。高风险动作（公开、生产、删除、强推、重置）仍单独确认。安全扫描或目标不明时停在当前步骤；完成过的步骤不重复执行。

## 并发与恢复状态机

在单一 Git 项目内优先将代码、索引、当前态与日志作为同一提交单元；若无权提交，保持工作区改动并报告，不能伪称已完成。每次任务为日志分配稳定 ID：优先 `PC-<UTC基本时间>-<随机短串>` 或 UUID，不使用按文件行数推断的流水号。重试先在日志和 Git 历史查询已有 ID；若已写则更新未完成步骤，不追加第二条成功记录。提交前重新检查工作区与目标分支；推送拒绝时 `fetch` 并审查分叉，保留原提交，必要时新建安全分支但不覆盖/强推。再次同步只在可安全 fast-forward 或经授权消解冲突后执行。

跨项目仓库和 hub **不存在原子事务**：先确认项目侧状态，后写 hub 指针。项目已同步但 hub 未同步：项目事实有效，交接待完成；hub 已存在 WIP 但项目推送失败：交接只引用本地不可跨设备的残留不得称接手可用，需将可达工作安全保存或标明不可接手。恢复时分别核对两个目标的远端 revision，不能重复建项目/重复追加日志。

## 非 Git 知识库最低契约

绑定时记录稳定项目 ID、可发现的权威地址、认证方式的**名称而非凭据**、读取 revision/ETag 的方法、以已读 revision 执行条件写入（如 HTTP `If-Match`/CAS）的能力、变更历史查询入口、同步核验方法、文件附件与导出策略。写入前读基线 revision；条件写失败保留草稿和新旧 revision，标 `CONFLICT/未同步`，不自动覆盖；写入成功再复读验证。缺版本/条件写入或不可验证远端成功时只能只读，或经明确许可输出待人工应用的补丁；不能承诺自动同步一致。代码仓库和知识库分别为事实源时须定义字段归属，记录双版本与失配状态；不声称跨后端原子完成。
